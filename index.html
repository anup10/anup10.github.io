Archipelago Companies · 2026 · AI platform

The automation stack that made daily warehouse reporting touchless

Daily ops reporting across four brands and three markets took someone 2–3 hours every morning. I built the tool layer that lets AI agents do it instead.

Zero
human effort in a 2–3 hour daily task · the morning number lands ~4 hours earlier

Problem

Warehouse status depended on someone stitching 3PL exports to ERP pick tickets by hand, so the morning number was late and sometimes stale.

What I did

Automated the whole workflow. Plugins with cloud scheduled tasks fire at 5:00 AM daily: skills pull the overnight reports from the Outlook inbox through the Graph API, normalize them with convert.py on the Archipelago MCP server we built, land them in the operations team’s shared SharePoint directory, archive the previous day’s files and read the latest ones — then generate the summary and post it to the operations Slack channel.

Outcome

A job that took 2–3 hours every day now takes none. The whole chain runs unattended for all four brands across the US, UK and EU, the summary is waiting in Slack before the team starts, and the MCP server underneath it now carries Archipelago’s other agent workflows.

Archipelago Companies · 2026 · Integration

A Shopify → ERP order bridge where no direct connector existed

Four DTC brands were selling through Shopify, while fulfilment and inventory operations ran on Full Circle ERP — a system that exchanges data only through scheduled, file-based SFTP transfers.

$23K+
annual labor cost removed · 2.5K+ orders/day now flow untouched

Problem

No automated integration connected the SFTP process with Shopify, so files had to be moved and monitored by hand between the two systems — creating delays and operational risk across 2.5K orders a day.

What I did

Proposed and helped implement an automated integration using systems the organization already had: Pipe17 handled the Shopify-side file exchange, Couchdrop provided the SFTP layer, and Full Circle’s scheduled jobs picked up the inbound files and returned fulfilment, tracking and inventory updates through the same route. We then used n8n as the monitoring and orchestration layer — verifying each handoff, detecting missing, delayed or duplicate files, and alerting the team in Slack when something needed attention.

Outcome

The flow works in both directions: order data moves from Shopify into Full Circle, while fulfilment, tracking and inventory updates flow back to Shopify. Once the architecture was working for one brand we standardized it and rolled it out across all four — $23K+ of annual labor removed, and failures surface as Slack alerts rather than as a mismatch found later.

Archipelago Companies · 2026 · Finance operations

Automating the accounting cycle without giving up the controls

Three manual jobs in the cash cycle — reading remittance advices, matching deposits to invoices, and assembling the payment-run import. Each now runs as a skill that deliberately stops short of the ledger, and all three were delivered into production.

~1 min
per remittance advice, down from about an hour by hand · output verified line for line against the team’s own file

Problem

Major customers pay hundreds of invoices in one transfer, and the advice listing them runs from a handful of lines to several thousand. Reading one by hand took about an hour and could be quietly wrong. On the payables side, the ERP’s import workbook was assembled by hand from three brands’ aging reports, with routing and exclusion rules that lived in people’s heads.

What I did

Built each step to the same shape: a deterministic script does the arithmetic, the model orchestrates, and every run is checked against totals the customer or the team stated independently. A run that can’t reconcile refuses to produce a file at all — a partly-correct cash file is worse than none — and nothing posts to the ERP, so each skill ends at a file a person reviews.

Outcome

All three run in production. Remittance extraction covers five major customers across three brands, and one generated file came back identical to the team’s hand-built version line for line, across 4,931 rows. Deposit reconciliation matches the day’s deposits to invoices and writes proposed matches for review. The payables importer produces the ERP’s import workbook with its exclusion list as a first-class output, so the reviewer sees exactly what was left out.

Archipelago Companies · 2026 · Data platform migration

Taking Power BI out of the middle of a planning workflow

Melin’s ops team used Power BI as a data warehouse. ERP files arrived by email and were carried into SharePoint by hand, then mapped and enriched inside the semantic model.

17 → 0
manual actions a day, eliminated · the fulfilment report went from weekly to daily

Problem

Eight raw ERP exports arrived by email each night and were moved into SharePoint by hand — around 17 manual actions a day before anyone looked at a number. Everything downstream lived inside a Power BI model doing a job it wasn’t built for, and the fulfilment report was rebuilt weekly.

What I did

Replaced the whole path. A dedicated SFTP user per export slot removed the hand-carrying, so files flow Full Circle → Couchdrop → SharePoint with a dated archive copy written on arrival. Then I read the semantic model’s own TMDL definition to extract every Power Query M transform and DAX column and re-implemented them as a deterministic Python transform, packaged as scheduled skills that verify their own inputs and outputs.

Outcome

Power BI is retired as the warehouse and modelling layer for Melin’s fulfilment and planning workflow. The report went from weekly to daily — it rebuilds every weekday at 9:00 AM from enriched workbooks the team’s existing pivots read directly. Ten consecutive business days running beside Power BI matched it on 11 headline metrics with zero variance, and that record is what justified the cutover.
